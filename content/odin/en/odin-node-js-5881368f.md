# Backend conclusion and next steps

## What you can now build

After completing the backend projects, you can design interfaces, sessions, permissions and persistent data. Completion does not mean knowing everything; it gives you tools to investigate new problems. The next curriculum course covers getting hired.

Trace one social-network request from browser to PostgreSQL and back. Justifying validation, authorization, queries and responses establishes a foundation you can extend.

## Continue learning

Node has a large ecosystem. Teamwork exposes real maintenance, while independent projects and documentation also develop judgment. Read [Node.js](https://nodejs.org/en/docs/) and [Next.js](https://nextjs.org/docs) systematically: select an unfamiliar API, build a small experiment and record results.

### Security

Public applications receive unexpected input. Review [Next data security](https://nextjs.org/docs/app/guides/data-security), dependencies, validation, sessions, permissions, limits and logs. The original [Express security practices](https://expressjs.com/en/advanced/best-practice-security.html) remain a comparison of responsibilities.

### Caching

Caching reduces repeated queries but introduces freshness and invalidation. First distinguish shareable and account-specific data. Explore [Redis](https://redis.io/) for appropriate temporary storage or when encountered in projects and job descriptions. Establish a policy and measurement before adding cache.

### Non-relational data

PostgreSQL is not the only model. Explore [Learn MongoDB](https://learn.mongodb.com), comparing queries, relationships, transactions and consistency. Do not switch databases simply for novelty.

## Contribute

The Odin Project is open source. Correct an explanation, reproduce a bug or improve documentation in its [repository](https://github.com/TheOdinProject/curriculum). Read contribution instructions and propose small evidence-backed changes. Contributing also develops collaboration and review skills.

## Assignment

1. Study [Next caching](https://nextjs.org/docs/app/getting-started/caching), optionally comparing the [original Express reference](https://expressjs.com/en/advanced/best-practice-performance.html#cache-request-results).
2. Explore the [Odin community](https://discordapp.com/channels/505093832157691914/505093832157691916); participation is optional.
3. Improve one concrete aspect of the final project: an authorization test, slow query or deployment failure. Document before and after.
4. Continue to Getting Hired.
