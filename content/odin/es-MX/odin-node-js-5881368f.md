# Conclusión y próximos pasos en backend

## Lo que ya puedes construir

Después de completar los proyectos de backend puedes diseñar aplicaciones con interfaces, sesiones, permisos y datos persistentes. Haber terminado no significa conocer todo; significa tener herramientas para investigar y construir problemas nuevos. La siguiente parte del currículo es preparación para conseguir trabajo.

Revisa tu proyecto de red social: explica una solicitud desde el navegador hasta PostgreSQL y de vuelta. Si puedes justificar validación, autorización, consultas y respuesta, tienes una base que podrás extender.

## Sigue aprendiendo

Node tiene un ecosistema amplio. Trabajar en equipo permite aprender del mantenimiento real, pero construir proyectos y leer documentación también desarrolla criterio. Consulta [Node.js](https://nodejs.org/en/docs/) y [Next.js](https://nextjs.org/docs) de manera sistemática: identifica una API desconocida, crea un ejemplo pequeño y registra lo observado.

### Seguridad

Las aplicaciones públicas reciben entradas imprevistas. Revisa [seguridad de datos en Next](https://nextjs.org/docs/app/guides/data-security), dependencias, validación, sesiones, permisos, límites y logs. Las [prácticas de seguridad Express](https://expressjs.com/en/advanced/best-practice-security.html) del original sirven como comparación de responsabilidades, aunque no uses ese framework.

### Caché

La caché reduce consultas repetidas, pero introduce preguntas de frescura e invalidación. Aprende primero qué dato puede compartirse y cuál pertenece a una cuenta. Explora [Redis](https://redis.io/) si necesitas almacenamiento temporal o lo encuentras en proyectos y ofertas laborales. No agregues caché antes de tener una regla clara y una forma de medir.

### Datos no relacionales

PostgreSQL no es la única opción. Las bases documentales resuelven otros modelos; explora [Learn MongoDB](https://learn.mongodb.com) y compara consultas, relaciones, transacciones y consistencia. No cambies de base solo por novedad.

- [Más sobre APIs](https://www.youtube.com/watch?v=oBW_VNg4qD0).
- [Design Patterns](https://www.amazon.com/Design-Patterns-Object-Oriented-Addison-Wesley-Professional-ebook/dp/B000SEIBB8), referencia opcional de patrones.
- [Clean Code](https://www.amazon.com/Clean-Code-Handbook-Software-Craftsmanship-ebook/dp/B001GSTOAM/ref=sr_1_1?dchild=1&keywords=Clean+Code&qid=1602168590&s=digital-text&sr=1-1), lectura opcional para discutir mantenibilidad; no necesitas comprarlo para completar el curso.
- [Syntax.fm](https://syntax.fm) y el [blog oficial de Node](https://nodejs.org/en/blog/).
- La [lista histórica de frameworks sobre Express](https://web.archive.org/web/20240328030121/https://expressjs.com/en/resources/frameworks.html) muestra cómo cambia el ecosistema; no es una lista de tecnologías obligatorias.

## Contribuir

The Odin Project es abierto. Puedes corregir una explicación, reproducir un error o mejorar documentación en su [repositorio](https://github.com/TheOdinProject/curriculum). Lee las instrucciones de contribución y presenta cambios pequeños con evidencia. Participar también permite practicar revisión y colaboración.

## Actividad

1. Estudia [caché en Next](https://nextjs.org/docs/app/getting-started/caching). Compárala, si te interesa, con la [referencia original de caché Express](https://expressjs.com/en/advanced/best-practice-performance.html#cache-request-results).
2. Explora la [comunidad de Odin](https://discordapp.com/channels/505093832157691914/505093832157691916); participar es opcional.
3. Elige una mejora concreta de tu proyecto final: un test de permisos, una consulta lenta o un error de despliegue. Documenta antes/después.
4. Continúa con el curso de búsqueda de empleo.
