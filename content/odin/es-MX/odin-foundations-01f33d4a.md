# Continúa después de Fundamentos

Ya recorriste HTML, CSS y JavaScript, organizaste archivos con la terminal y publicaste proyectos con Git. Antes de continuar, reconoce qué puedes hacer: explicar una solicitud web, estructurar una página, distribuir contenido y responder a eventos. Si alguna pieza todavía depende de copiar sin entender, vuelve a ese ejercicio y reconstruye una parte pequeña.

## La ruta de esta edición

El original presenta varias rutas tecnológicas. Ruta continúa deliberadamente con **Full Stack JavaScript**, profundizando HTML y CSS, JavaScript, React, bases de datos y conceptos de servidor, y adaptando la construcción de aplicaciones a Next.js. No necesitas elegir otra tecnología ni usar una ruleta para avanzar.

Node permite utilizar JavaScript fuera del navegador. Compartir lenguaje entre cliente y servidor reduce cambios de sintaxis y puede permitir reutilizar lógica, pero no elimina sus responsabilidades distintas. Un navegador no debe recibir secretos del servidor y no todas las APIs existen en ambos entornos.

Las herramientas de servidor más pequeñas dejan muchas decisiones de estructura a quien desarrolla. Un framework como Next.js propone convenciones para rutas y renderizado. Aprenderás qué problemas resuelven esas convenciones; no son una razón para saltar HTTP, validación, autenticación o bases de datos. JavaScript moderno utiliza motores con compilación y optimizaciones, pero que una tecnología sea rápida no convierte automáticamente todo programa en eficiente.

## Habilidades que se transfieren

Programar es más que aprender un lenguaje: investigar, descomponer problemas, trabajar en un código compartido, comunicar decisiones y comprobar resultados. Esas habilidades te servirán si después aprendes otro lenguaje. Una buena base hace ese siguiente aprendizaje más accesible; cambiar de ruta cada vez que aparece una dificultad impide consolidarla.

Puedes investigar oportunidades locales y remotas para entender requisitos de empleo, pero ninguna elección de lenguaje garantiza una contratación. Construir proyectos que puedas explicar y sostener una práctica consistente es más útil que buscar constantemente la tecnología supuestamente perfecta. El [artículo sobre elegir un lenguaje](https://medium.com/@bycdiaz/choosing-the-right-language-a-short-guide-on-how-not-to-ruin-your-career-2b353be1371) amplía esta perspectiva.

## Cierre de etapa

Abre tus proyectos desde sus instrucciones, verifica enlaces publicados y lee el historial. Elige un fallo que resolviste y explica cómo lo investigaste. Después anota una limitación de cada proyecto que todavía no sabes resolver: esas preguntas conectan Fundamentos con el material siguiente.

No necesitas convertir cada ejercicio en un producto completo antes de seguir. Sí necesitas poder explicar sus decisiones principales y reconocer cuándo consultar documentación. Mantén esa mentalidad de aprendizaje durante el resto del programa y después de él.

## Decide con evidencia qué repasar

Para revisar tu base, intenta explicar un proyecto sin abrir primero su código. Describe la entrada, el estado y la salida, y después comprueba si la implementación coincide. Si puedes seguir una función pero no sabes por qué se llama en cierto momento, repasa eventos y flujo de ejecución. Si un cambio visual se arregla sólo añadiendo márgenes al azar, vuelve al modelo de caja y a los ejes de flexbox.

No necesitas aprender un segundo lenguaje para resolver esas dudas. Profundizar en los conceptos que ya utilizaste te prepara para herramientas posteriores, donde las mismas responsabilidades aparecen bajo convenciones nuevas. Mantén una lista pequeña de preguntas concretas y úsala para orientar tu próxima práctica, no para declarar todo el curso incompleto en tu cabeza.
