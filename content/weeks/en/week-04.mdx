# Build interactive web experiences

Connect JavaScript to the document, manage user events, persist small preferences, and consume public APIs with honest loading, empty, and failure states. This audit source assumes no prior programming experience and supports Windows and macOS. Complete the lessons in order: each one moves from explanation to a concrete example, guided practice, and observable evidence before the weekly project.

## DOM and events

### Explanation

Query stable elements, listen for intentional events, update only the affected region, and use event delegation when repeated controls share behavior. The goal is not to memorize isolated syntax. You should be able to name the input, the decision made at each step, and the evidence that shows the result is correct. Predict before copying. If reality differs, reduce the case until one cause is understandable. This habit replaces random trial and error with a repeatable way to learn and ask for help.

### Example

Read the example from top to bottom and point out the input, transformation, and result. Type it into a scratch file instead of pasting it; typing makes punctuation, names, and structure visible.

```js
const list = document.querySelector("[data-list]");
list.addEventListener("click", (event) => {
  const button = event.target.closest("button");
  if (button) button.closest("li").remove();
});
```

If you get stuck, return to the smallest example, read the first complete error, and change one thing. Ask for help with your prediction, the actual result, and what you tried—never with a password or token.

### Guided exercise

1. Create a disposable folder or file for this lesson and write one concrete prediction before running the example.
2. Type the example, run or inspect it with the appropriate tool, and compare the result with your prediction. Preserve the exact message if it fails.
3. Add list items after the listener is registered and verify the same delegated handler works for new buttons.
4. Commit only when the change belongs in your project; for disposable practice, record the lesson in your learning notes instead.

### Checkpoint

- Connect events without inline JavaScript. Show this with a run, capture, test, or explanation in your own words; repeating the sentence is not evidence.
- Preserve focus after dynamic updates. Show this with a run, capture, test, or explanation in your own words; repeating the sentence is not evidence.

## Weekly project

Use one documented public dataset to let people search or filter useful information. Cache only non-sensitive preferences and explain the source and update date.

### Deliverables

- A responsive search or filter interface with loading, empty, success, and recoverable error states.
- A public HTTPS API integration with response-shape checks and a visible data-source link.
- A manual test checklist covering keyboard use, slow network, malformed data, and offline failure.

Before submitting, open the project from a clean session, complete the primary journey, and connect each rubric criterion to concrete evidence. Never include passwords, tokens, precise locations, or real personal data.
