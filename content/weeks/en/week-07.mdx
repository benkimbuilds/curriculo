# Build with the Next.js App Router

Create a routed full-stack application, decide deliberately between server and client components, and validate forms on both sides of the network. This audit source assumes no prior programming experience and supports Windows and macOS. Complete the lessons in order: each one moves from explanation to a concrete example, guided practice, and observable evidence before the weekly project.

<!-- lesson:week-07-lesson-01 -->
## Routes, layouts, and navigation

### Explanation

Map URLs to user tasks, create nested layouts for shared structure, use links for navigation, and design not-found and error experiences as part of the route tree. The goal is not to memorize isolated syntax. You should be able to name the input, the decision made at each step, and the evidence that shows the result is correct. Predict before copying. If reality differs, reduce the case until one cause is understandable. This habit replaces random trial and error with a repeatable way to learn and ask for help.

### Example

Read the example from top to bottom and point out the input, transformation, and result. Type it into a scratch file instead of pasting it; typing makes punctuation, names, and structure visible.

```text
/opportunities        browse
/opportunities/[id]   inspect one
/opportunities/new    propose one
```

If you get stuck, return to the smallest example, read the first complete error, and change one thing. Ask for help with your prediction, the actual result, and what you tried—never with a password or token.

### Guided exercise

1. Create a disposable folder or file for this lesson and write one concrete prediction before running the example.
2. Type the example, run or inspect it with the appropriate tool, and compare the result with your prediction. Preserve the exact message if it fails.
3. Add loading, not-found, and access expectations to each route before creating the matching folders.
4. Commit only when the change belongs in your project; for disposable practice, record the lesson in your learning notes instead.

### Checkpoint

- Create a route map before making folders. Show this with a run, capture, test, or explanation in your own words; repeating the sentence is not evidence.
- Use navigation that preserves browser expectations. Show this with a run, capture, test, or explanation in your own words; repeating the sentence is not evidence.

## Weekly project

Create a full-stack directory of fictional training and volunteering opportunities with browse, detail, search, and create flows. Keep moderation status explicit.

### Deliverables

- A route map with server-rendered list and detail pages plus purposeful loading, error, and not-found views.
- An accessible create form with trusted server validation and duplicate-submission protection.
- Tests for domain validation and the main form path, with deployment and architecture notes.

Before submitting, open the project from a clean session, complete the primary journey, and connect each rubric criterion to concrete evidence. Never include passwords, tokens, precise locations, or real personal data.
