# Descubre y construye el alfa de tu proyecto final

Encuentra una necesidad local real y segura, valídala con investigación ligera, reduce alcance, diseña el sistema y entrega un corte completo de principio a fin. Esta edición está escrita para quien empieza desde cero y puede trabajar en Windows o macOS. Completa las lecciones en orden: cada una incluye explicación, ejemplo, práctica y evidencia antes del proyecto semanal.

<!-- lesson:week-11-lesson-01 -->
## Descubrimiento del problema

### Explicación

Entrevista u observa sin recolectar información sensible innecesaria. Separa lo dicho, lo inferido y lo desconocido; no empieces desde una tecnología favorita. La meta no es memorizar sintaxis aislada, sino poder explicar qué información entra, qué decisión toma cada paso y qué evidencia muestra que funciona. Antes de copiar algo, predice el resultado. Si el resultado cambia, reduce el caso hasta entender una sola causa. Este hábito evita que una persona principiante dependa de ensayo y error y deja una ruta clara para pedir ayuda.

### Ejemplo

Lee el ejemplo de arriba hacia abajo y señala qué parte representa entrada, transformación y resultado. Escríbelo a mano en un archivo de práctica: teclear obliga a notar puntuación, nombres y estructura que se pierden al copiar y pegar.

```text
Evidence: three learners lose track of application deadlines.
Inference: reminders may help.
Unknown: whether they want email or a checklist.
```

Si te atoras, vuelve al ejemplo mínimo, lee el primer error completo y cambia una sola cosa. Pide ayuda compartiendo la predicción, el resultado real y lo que ya probaste, nunca una contraseña o token.

### Ejercicio guiado

1. Crea una carpeta o archivo desechable para esta lección y escribe una predicción concreta antes de ejecutar el ejemplo.
2. Teclea el ejemplo, ejecútalo o revísalo con la herramienta apropiada y compara el resultado con tu predicción. Conserva el mensaje exacto si falla.
3. Reescribe una idea centrada en tecnología como problema y elimina detalles que podrían identificar participantes.
4. Haz un commit sólo si el cambio pertenece a tu proyecto; si era práctica desechable, resume en tus notas lo que aprendiste.

### Comprobación

- Escribir notas sin identificar participantes. Muéstralo con una ejecución, captura, prueba o explicación propia; repetir la frase no cuenta como evidencia.
- Definir un problema sin esconder una solución. Muéstralo con una ejecución, captura, prueba o explicación propia; repetir la frase no cuenta como evidencia.

## Proyecto semanal

Diseña un producto web útil para una necesidad mexicana de comunidad, educación, trabajo, ambiente, cultura o servicio, sin exigir datos personales sensibles.

### Entregables

- Brief con evidencia, usuario principal, no-objetivos, señal de éxito, riesgos y decisiones de privacidad.
- Mapa de arquitectura y backlog priorizado con criterios de aceptación.
- Corte vertical desplegado con historial, pruebas principales, retroalimentación alfa y decisiones siguientes.

Antes de entregar, abre el proyecto desde una sesión limpia, recorre el flujo principal y compara cada criterio de la rúbrica con evidencia concreta. No incluyas contraseñas, tokens, ubicaciones precisas ni datos personales reales.
