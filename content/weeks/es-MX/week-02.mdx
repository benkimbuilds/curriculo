# Diseña páginas responsivas e incluyentes

Usa CSS con intención, adapta interfaces desde teléfonos hasta monitores del laboratorio y verifica que funcionen con teclado y tecnologías de asistencia. Esta edición está escrita para quien empieza desde cero y puede trabajar en Windows o macOS. Completa las lecciones en orden: cada una incluye explicación, ejemplo, práctica y evidencia antes del proyecto semanal.

<!-- lesson:week-02-lesson-01 -->
## Fundamentos de CSS

### Explicación

Una hoja de estilos no se ejecuta de arriba abajo como una secuencia de instrucciones JavaScript. El navegador reúne declaraciones que coinciden con cada elemento y resuelve conflictos mediante la cascada. Entre reglas normales de autor de una misma capa, la especificidad ayuda a decidir cuál gana; si empatan, gana la posterior. La herencia es otro mecanismo: algunas propiedades, como el color del texto, pasan desde un padre cuando el hijo no tiene su propia declaración ganadora.

Considera un párrafo con clase notice dentro de main. Coinciden tanto el selector de clase como el selector que añade main como ancestro. El segundo incluye un componente de tipo adicional y su color gana frente a las dos reglas de clase del ejemplo. Mover una regla menos específica al final no hace que venza automáticamente. Evita responder primero con important: investiga qué regla gana y expresa claramente la relación que necesitas.

Los espacios tienen otro modelo. Cada caja tiene contenido, relleno, borde y margen. El relleno separa el contenido de su borde; el margen separa la caja de sus vecinas. Con content-box, el ancho declarado no incluye relleno ni bordes. Con border-box, sí los incluye. Si un título toca la línea de una tarjeta, normalmente falta relleno interior; aumentar el margen entre tarjetas no corrige esa relación.

Elige unidades según la relación deseada. Un rem sigue la fuente raíz; un em puede seguir la fuente del elemento. Un borde fino puede usar píxeles deliberadamente. No hay una unidad universal: pregunta qué debe crecer cuando crece el texto. Después comprueba las preferencias tipográficas del navegador y el zoom, porque una caja con altura fija todavía puede recortar contenido aunque uses fuentes relativas.

### Ejemplo

```css
*, *::before, *::after { box-sizing: border-box; }
.notice { color: navy; }
main .notice { color: teal; }
.notice { color: purple; }
.card {
  max-width: 36rem;
  padding: 1.5rem;
  border: 1px solid #667788;
  margin-block: 1rem;
}
.card p { line-height: 1.5; }
```

Crea un párrafo dentro de una tarjeta dentro de main. Abre DevTools, selecciona el párrafo y revisa Styles y Computed. Las declaraciones tachadas muestran reglas que pierden; el color calculado muestra el resultado. Después inspecciona el diagrama de caja de la tarjeta. Compara borde de contenido, relleno y borde visible en lugar de cambiar números al azar.

### Ejercicio guiado

1. Crea HTML con main, dos tarjetas, encabezados, párrafos y un enlace. Conecta una hoja externa y comprueba que su solicitud carga correctamente.
2. Aplica el ejemplo y predice el color antes de abrir Computed. Desactiva la regla ganadora y explica cuál gana después y por qué.
3. Quita el relleno de la tarjeta, observa el texto pegado al borde y restáuralo. Cambia el margen por separado y explica la diferencia visible.
4. Añade un título largo y aumenta el tamaño de texto del navegador. Sustituye cualquier altura fija que recorte contenido por altura natural o un mínimo justificado.
5. Lee la [guía de cascada de MDN](https://developer.mozilla.org/en-US/docs/Learn/CSS/Building_blocks/Cascade_and_inheritance) y la [guía del modelo de caja](https://developer.mozilla.org/en-US/docs/Learn/CSS/Building_blocks/The_box_model). Registra una regla inspeccionada y una corrección de espacio medida.

### Comprobación

- Explica por qué gana teal y muestra las declaraciones competidoras en DevTools.
- Identifica contenido, relleno, borde y margen, y demuestra qué cambio separa el texto de la línea.
- Muestra que el texto largo sigue visible al aumentar la fuente.

## Sistemas de layout

### Explicación

Empieza con el flujo normal del documento. Encabezados y párrafos ya se apilan y el texto cambia de línea dentro del espacio disponible. No necesitas un sistema especial de colocación para cada elemento. Introduce Flexbox cuando un grupo requiera comportamiento coordinado sobre un eje principal y Grid cuando filas y columnas deban compartir una estructura.

Una fila de acciones es un buen caso de Flexbox. Cada botón tiene un tamaño natural por su contenido; el grupo puede alinear elementos, mantener huecos y cambiar de línea cuando ya no caben. El eje principal depende de flex-direction. Justify-content distribuye sobre ese eje y align-items actúa sobre el transversal. Si cambias la dirección, no supongas que la misma propiedad siempre significa alineación horizontal.

Una galería de proyectos es un buen caso de Grid. El contenedor define pistas de columna y sus hijos directos ocupan celdas. Repeat con auto-fit y minmax permite decidir cuántas columnas legibles caben sin identificar un teléfono concreto. Un máximo de una fracción reparte el espacio restante. El mínimo también debe caber: imponer dieciséis rem sin considerar un contenedor más pequeño puede producir desbordamiento.

Ambas herramientas se complementan. Una tarjeta puede ser hija Grid en la galería y contener una fila Flex para sus acciones. Son relaciones de niveles distintos. Poner display flex sobre la tarjeta no modifica las columnas de la galería exterior. Identifica primero el padre responsable de distribuir los elementos que quieres cambiar.

El contenido introduce restricciones. Una URL larga, una imagen grande o una etiqueta que no puede partirse pueden imponer mínimos que resisten reducirse. Inspecciona al hijo responsable en lugar de ocultar el desbordamiento de toda la página. Usa un ancho mínimo cero cuando corresponda permitir reducción y una regla de partición para texto largo. Conserva un orden HTML lógico aunque Grid permita mover visualmente una tarjeta a otra región.

### Ejemplo

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr));
  gap: 1.5rem;
}
.card { min-width: 0; padding: 1.5rem; border: 1px solid #9aa7b0; }
.card h2 { overflow-wrap: anywhere; }
.actions { display: flex; flex-wrap: wrap; gap: .75rem; align-items: center; }
.actions a { padding: .75rem 1rem; }
```

El gap de la galería separa tarjetas; el padding de cada tarjeta separa texto y borde. El gap de las acciones separa controles. Aumentar la primera separación no arregla el texto apretado dentro de la tarjeta. Activa la superposición Grid para ver pistas y usa el modelo de caja para inspeccionar relleno.

### Ejercicio guiado

1. Construye seis tarjetas con título, descripción y dos enlaces reales. Mantén el marcado en el orden de lectura previsto.
2. Aplica el ejemplo e inspecciona las pistas. Reduce el padre hasta perder una columna y explica qué mínimo y huecos causaron el cambio.
3. Sustituye un título por una URL larga y una descripción por varios párrafos. Comprueba que las tarjetas crecen verticalmente sin recortar.
4. Añade una tercera acción con etiqueta larga. Observa cómo Flexbox acomoda acciones independientemente de las columnas Grid.
5. Compara [Grid](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_grid_layout) y [fundamentos de Flexbox](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_flexible_box_layout/Basic_concepts_of_flexbox). Escribe una razón para cada sistema usado.

### Comprobación

- Identifica qué contenedor controla la galería y cuál controla los botones.
- Demuestra una tarjeta adicional y un título largo sin añadir reglas por dispositivo.
- Explica por qué gap, padding y altura fija no son soluciones intercambiables.

## Diseño responsivo

### Explicación

Una implementación responsiva conserva una interfaz utilizable cuando cambia el espacio disponible. Una página puede verse correcta en un teléfono y en escritorio, pero fallar en anchos intermedios. Prueba un rango continuo y varía también el contenido. El zoom y el texto aumentado cambian cuánto espacio efectivo tiene cada región.

Empieza con una distribución estrecha que funcione en el flujo normal. Deja crecer los contenedores hasta un máximo legible y céntralos, en lugar de extender párrafos por toda una pantalla muy ancha. Las imágenes deben tener ancho máximo flexible y altura automática para conservar proporción. Si una fotografía necesita llenar un marco, utiliza object-fit deliberadamente y revisa que el recorte no elimine al sujeto.

Una consulta de medios aplica declaraciones cuando el viewport cumple una condición. No añade especificidad ni anula automáticamente la cascada. Elige el punto de cambio cuando el contenido necesita otra distribución, no porque una lista de dispositivos diga que las tabletas empiezan en cierto número. Una barra lateral puede pasar encima del artículo cuando ya no caben ambos. Una fila pequeña de acciones quizá sólo necesita cambiar de línea y ninguna consulta.

La etiqueta viewport indica al navegador móvil que utilice el ancho disponible en píxeles CSS en lugar de reducir una página artificialmente amplia. Establece una escala inicial; no debe impedir que la persona amplíe. Algunas herramientas ya generan esta etiqueta: inspecciona el documento resultante antes de duplicarla.

Los formularios revelan errores responsivos rápidamente. Una etiqueta puede ocupar dos líneas, un error puede ser largo y el teclado virtual reduce el área visible. Coloca etiquetas arriba de campos cuando eso evita columnas apretadas, permite que los controles llenen su contenedor y evita alturas fijas en errores. No elimines instrucciones en móvil sólo para que una captura parezca ordenada.

### Ejemplo

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

```css
.page { width: min(100% - 2rem, 70rem); margin-inline: auto; }
img { max-width: 100%; height: auto; }
.content { display: grid; gap: 2rem; }
input, textarea, select { max-width: 100%; font: inherit; }
@media (min-width: 52rem) {
  .content { grid-template-columns: minmax(0, 2fr) minmax(14rem, 1fr); }
}
```

Debajo del punto de cambio, las regiones se apilan siguiendo el HTML. Encima, forman una columna principal y otra secundaria. El mínimo lateral es una decisión consciente: comprueba que la columna principal aún tenga espacio suficiente en el instante exacto en que se activa la distribución.

### Ejercicio guiado

1. Añade a tu galería una introducción, una imagen grande y un formulario breve para pedir información, con etiquetas visibles.
2. Prueba a 320, 360, 768 y 1280 píxeles CSS. Después cambia lentamente entre esos anchos y anota dónde empieza a apretarse el contenido.
3. Añade una consulta sólo para un cambio estructural necesario. Prueba justo debajo, en el punto exacto y justo encima.
4. Aumenta zoom al 200%, introduce un correo ficticio largo y muestra un error de varias líneas. Comprueba que nada desaparece detrás de cajas fijas.
5. Si hay desplazamiento horizontal, identifica el elemento responsable y corrige ancho, mínimo o partición. No encubras el problema con overflow hidden en el documento.
6. Sigue la [introducción responsiva de MDN](https://developer.mozilla.org/en-US/docs/Learn/CSS/CSS_layout/Responsive_Design) y el [modo de dispositivo de Chrome](https://developer.chrome.com/docs/devtools/device-mode/). Guarda capturas y explica qué condición justificó el breakpoint.

### Comprobación

- Muestra el mismo contenido en anchos estrechos, intermedios y amplios sin pérdida de información.
- Explica por qué existe el punto de cambio y demuestra su comportamiento cercano.
- Comprueba proporciones de imágenes y uso del formulario con texto aumentado.

## Accesibilidad práctica

### Explicación

La accesibilidad forma parte de poder completar una tarea. Para esta semana, revisa un recorrido concreto: encontrar el servicio, entender sus condiciones, introducir una solicitud y reconocer el resultado o error. Una página visualmente pulida que no puede operarse con teclado no ha completado ese recorrido para todas las personas.

Usa HTML semántico antes de añadir ARIA. Un botón realiza una acción; un enlace con href navega. Un div con apariencia de botón no recibe automáticamente foco, activación con Enter o Espacio ni anuncio de su función. Los encabezados describen jerarquía y main y nav identifican regiones importantes. Elige niveles de encabezado por estructura y cambia su apariencia con CSS.

Cada entrada necesita una etiqueta significativa. El valor for de la etiqueta debe coincidir con un id único. Name cumple otra función: identifica el dato enviado. Usa email para correo, tel para teléfono y texto para identificadores que no son cantidades. Un placeholder es una pista que desaparece y no sustituye una etiqueta persistente.

Explica restricciones antes de enviar. Required, minlength y la validación por tipo ofrecen una primera capa útil, pero las comprobaciones del navegador no protegen al servidor. Un formulario de demostración no debe fingir que crea una cuenta real. Cuando aparezca un error, identifica el campo y cómo corregirlo conservando lo que la persona ya escribió. Asocia instrucciones adicionales mediante aria-describedby cuando corresponda.

Quien navega con teclado necesita foco visible y orden comprensible. Tab y Shift+Tab deben seguir lógicamente el documento; Enter y Espacio deben activar controles nativos según corresponda. Los paneles cerrados no deben contener paradas de foco invisibles. Conserva el indicador del navegador o reemplázalo por uno claro, y comprueba que bordes o reglas de overflow no lo recorten.

Colores e imágenes también comunican información. Comprueba contraste entre texto y fondo, distingue enlaces con algo más que color y escribe alternativas según la función de cada imagen. Las decorativas pueden tener alt vacío. Si añades movimiento, ofrece una alternativa de movimiento reducido que mantenga disponible la información.

### Ejemplo

```html
<form action="/solicitud" method="post">
  <label for="correo">Correo (obligatorio)</label>
  <p id="correo-ayuda">Usaremos esta dirección para responder sobre el taller.</p>
  <input id="correo" name="correo" type="email" required
         autocomplete="email" aria-describedby="correo-ayuda">
  <button type="submit">Solicitar información del taller</button>
</form>
```

```css
:focus-visible { outline: 3px solid #155b9e; outline-offset: 3px; }
label, input { display: block; }
input { width: 100%; padding: .75rem; margin-block: .5rem 1rem; }
```

La ruta es ilustrativa: conecta un manejador real o identifica claramente la página como demostración. Inspecciona nombre y descripción accesibles del campo; después pulsa la etiqueta para comprobar que el foco llega a la entrada.

### Ejercicio guiado

1. Completa toda la página sólo con Tab, Shift+Tab, Enter y Espacio. Registra la primera parada ausente o confusa.
2. Revisa el orden de encabezados y reemplaza contenedores genéricos interactivos por elementos nativos adecuados.
3. Prueba datos vacíos e inválidos y corrígelos. Comprueba mensajes útiles y conservación de otros valores.
4. Verifica colores con [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/) y revisa imágenes con su [guía de texto alternativo](https://webaim.org/techniques/alttext).

- Muestra una etiqueta asociada, foco visible y una alternativa de imagen significativa.
- Distingue lo que comprobó la auditoría automática de lo que verificaste manualmente.

## Proyecto semanal

Diseña una página responsiva para un servicio local ficticio, como biblioteca, centro de reciclaje o taller comunitario. La acción principal debe funcionar sin mouse.

### Entregables

- Layouts responsivos a 360, 768 y 1280 píxeles CSS sin desbordamiento horizontal.
- Un recorrido completo con teclado, foco visible y etiquetas de formulario asociadas.
- Una nota breve que explique jerarquía, color, tipografía y revisiones de accesibilidad.

Antes de entregar, abre el proyecto desde una sesión limpia, recorre el flujo principal y compara cada criterio de la rúbrica con evidencia concreta. No incluyas contraseñas, tokens, ubicaciones precisas ni datos personales reales.
