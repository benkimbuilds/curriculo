# Fortalece, lanza y presenta tu proyecto final

Termina el alcance más valioso, prueba y observa producción, mejora tu historia de portafolio y practica una entrevista técnica y demo breves. Esta edición está escrita para quien empieza desde cero y puede trabajar en Windows o macOS. Completa las lecciones en orden: cada una incluye explicación, ejemplo, práctica y evidencia antes del proyecto semanal.

<!-- lesson:week-12-lesson-01 -->
## Pase de calidad y seguridad

### Explicación

Prueba reglas, denegaciones, teclado, pantallas angostas, red lenta y recuperación. Elimina secretos y recolección innecesaria antes de pulir detalles. La meta no es memorizar sintaxis aislada, sino poder explicar qué información entra, qué decisión toma cada paso y qué evidencia muestra que funciona. Antes de copiar algo, predice el resultado. Si el resultado cambia, reduce el caso hasta entender una sola causa. Este hábito evita que una persona principiante dependa de ensayo y error y deja una ruta clara para pedir ayuda.

### Ejemplo

Lee el ejemplo de arriba hacia abajo y señala qué parte representa entrada, transformación y resultado. Escríbelo a mano en un archivo de práctica: teclear obliga a notar puntuación, nombres y estructura que se pierden al copiar y pegar.

```text
High: another user can edit a project -> block launch
Medium: slow empty state -> fix or document
Low: icon alignment -> defer
```

Si te atoras, vuelve al ejemplo mínimo, lee el primer error completo y cambia una sola cosa. Pide ayuda compartiendo la predicción, el resultado real y lo que ya probaste, nunca una contraseña o token.

### Ejercicio guiado

1. Crea una carpeta o archivo desechable para esta lección y escribe una predicción concreta antes de ejecutar el ejemplo.
2. Teclea el ejemplo, ejecútalo o revísalo con la herramienta apropiada y compara el resultado con tu predicción. Conserva el mensaje exacto si falla.
3. Clasifica cinco hallazgos por impacto, probabilidad y recuperación; resuelve seguridad y pérdida antes del detalle visual.
4. Haz un commit sólo si el cambio pertenece a tu proyecto; si era práctica desechable, resume en tus notas lo que aprendiste.

### Comprobación

- Priorizar riesgos de lanzamiento con evidencia. Muéstralo con una ejecución, captura, prueba o explicación propia; repetir la frase no cuenta como evidencia.
- Cerrar defectos importantes o documentar una limitación segura. Muéstralo con una ejecución, captura, prueba o explicación propia; repetir la frase no cuenta como evidencia.

## Proyecto semanal

Publica el recorrido principal en una URL HTTPS estable, preséntalo y crea un caso de estudio. El equipo es opcional, pero cada aportación debe ser explícita.

### Entregables

- Release con flujo principal, autorización, validación, revisiones responsivas y de teclado, monitoreo y rollback.
- Repositorio reproducible con pruebas, arquitectura, divulgaciones de privacidad e IA, commit desplegado y registro de aportación.
- Caso de estudio conciso, demo de tres minutos, bitácora de comentarios, retrospectiva y próximos pasos con evidencia.

Antes de entregar, abre el proyecto desde una sesión limpia, recorre el flujo principal y compara cada criterio de la rúbrica con evidencia concreta. No incluyas contraseñas, tokens, ubicaciones precisas ni datos personales reales.
